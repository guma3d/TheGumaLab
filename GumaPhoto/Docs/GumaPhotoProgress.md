# GumaPhoto 프로젝트 진행 상황 (Progress Log)

이 문서는 GumaPhoto 서비스의 개발 진행 상황과 중요 테스트/기술 결정 내역을 기록하는 공간입니다.

## 📌 [1단계] 인프라 및 기본 구조 셋업 세팅 (완료)
*   **Docker 및 FastAPI 구축:** 포트 매핑 및 Reverse Proxy 설정 완료.
*   **파일 시스템(Clean Architecture) 재정렬:** 
    *   어지럽게 분산되어 있던 수십 개의 테스트용/디버그용 스크립트 50여 개를 용도에 맞게 `DebugTool`, `Scripts`, `OneTimeFixes` 3대 하부 폴더로 질서정연하게 이동배치 (Git 통합 커밋 완료).
    *   루트 폴더는 가장 중요한 핵심 뼈대 파일 4개(`main.py`, `vector_indexer.py`, `organizer_pipeline.py`, `xmp_utils.py`) 만이 남아있도록 고도로 콤팩트화 됨.

## 📌 [2단계] 맞춤형 안면 인식 패러다임 점검 (완료)
*   **모델 업그레이드:** 초기 `DeepFace`에서 정확도가 압도적인 오픈소스 `InsightFace(buffalo_l)` 및 PyTorch 경량화 표정 엔진 `HSEmotion`으로 전격 세대교체 달성. (512차원 VRAM 보호 전략 탑재)

## 📌 [3단계] 갤러리 물리적 정리 및 파이프라인 무결점 고도화 (완료 🎯)
*   **네이밍 규칙 충돌(Collision) 방어 (확장자 무관화):** 
    *   기존에는 `_01.heic` 가 있어도 `_01.jpg`를 새로운 파일로 허용하여 태그 유실이 일어났었음.
    *   `glob.glob` 스캐너 기반으로 로직을 고쳐, 어떠한 대소문자나 확장자가 오더라도 **Base Name 앞쪽 이름만이 동일하면 무조건 빈 뒷번호나 완전 최하단 Max 번호로 자리 이동 (Hole-Filling)** 하도록 100% 방벽 세팅 완료.
*   **기존 충돌 파일(2,787개) 및 구멍 압축 자가 치료:**
    *   이미 동일 이름으로 부여받아 싸우고 있던 기존의 2,787개의 문제 파일들을 메타데이터 조작 0% 하에 `os.rename` 으로 완벽하게 안전 구출 진행(`rename_conflicts.py`).
    *   이후 밀려난 번호나 빈 이빨 빠진 공간을 1번부터 차근차근 다시 당겨 채우는 완벽 테트리스식 `compress_sequence.py` 정렬로 파일 시스템 최적화(Deffragmentation) 달성.
*   **Junk(쓰레기) 사본 즉시 청소기:** 파일 SHA-256 해시 검사를 통해 완전 복제된 사진, 영수증 비율, 심령사진 극도 블러를 완전 제거 적용함.
*   **글로벌 표준 한국어 강제 매핑 (Geocoding-Ko):**
    *   전 세계 어디서 휴대폰 사진이 올라와도, Nominatim GPS 역추적 API에 강제 `language='ko'` 부여.
    *   기존 생성된 2,000개의 끔찍한 영어 폴더들(예: Incheon-South-Korea) 안의 사진 1장씩을 조용히 꺼내 GPS 원본을 확인한 후 공식 한국어 매핑(경기도-성남시)으로 자동 폴더 통폐합 스크립트 실행 성공 (`translate_folders.py`).

## 📌 [4단계] 멀티모달 벡터 검색의 끝, 하이브리드 아키텍처 설계 (완료 🎯)
*   **다국어 SigLIP 768차원 + Florence-2 캡셔닝 융합:** 사진 한 장에 무려 4대의 거대 모델을 릴레이로 집어넣어, [분위기 + 사물 + 영어 문장 + 감정 + 얼굴 벡터 + 위치명] 이라는 막강한 Payload 조립 및 Qdrant 이식 방벽 구축 완료.
    *   **하드웨어 극한 튜닝 (RTX 4070 VRAM 방어 최적화):** Florence-2 모델의 정밀도를 `bfloat16`으로 극대화하고 런타임 컴파일 충돌(데드락) 우회를 위해 기본 Eager 어텐션을 채택하여 속도를 초고속으로 끌어올림.
    *   **최고의 안정성을 위한 여유 공간(Safety Buffer) 타협:** OOM 폭발 사고와 무한루프 환각 현상을 100% 방지하기 위하여 `repetition_penalty`, 토큰 256 구속, 그리고 **안전 `배치 10장` 단위**라는 최상의 황금비율 세팅에 합의 및 성공.
*   **자동 마스터 태그 사전 갱신(Self-Healing Vocab):** 인덱싱 엔진(`vector_indexer.py`) 구동이 끝나면 폴더를 역으로 훑어 100여 개의 공식적인 한국어 주소명만 추출해 `/app/data/available_tags.json` 사전에 자가 업데이트함.

## 📌 [5단계] AI 검색 엔진(LLM 파서)의 무결성 달성 (완료 🎯)
*   **"알래스카 할루시네이션(환각) 방어" 프롬프트 삽입:**
    *   자연어 검색어("알래스카에서 노는 송이") 발생 시, 서버의 위 마스터 사전을 참고. 
    *   단순 오타("하와잌")는 유추하되, 장부(사전)에 없는 완전한 타지("알래스카")는 기계적으로 무시하고 즉각 **빈 문자열('') 패스 로직**을 발동시키도록 Gemini 파싱 시스템에 정식 명문화. 무리한 유추 파기 확보.

## 📌 [6단계/유지보수] 100% 완전 파기 (Hard Delete & Ghost Prevent) (완료 🎯)
*   사용자 앱 모달에서 "휴지통" 클릭 시, 원본 사진 + DB 페이로드는 물론이고 짝을 잃어버릴 수 있는 `_heic.webp` 류의 **파생 썸네일(Webp) 파일까지 디스크에서 100% 동반 삭제토록 API 긴급 수정!** 이를 통해 스토리지 내 유령 쓰레기(Ghost Files) 적체 현상 완벽 봉쇄.

## 📌 [7단계] 100% 무결점 자율 진화 피드백 시스템 v2.0 (진행 중 🚀)
*   **단일 사진 집중 UI 도출:** 피드백 모달창에서 기존의 복잡했던 그리드창과 버튼들을 모조리 걷어내고, 미분류(Unknown) 사진 단 1장만을 거대하게 띄워 사용자가 직관적으로 교정할 수 있는 Focus Interface를 구축 완료. (도커 재시동 동결 명령에 따라 프론트엔드 Bypass 임시 파이프라인으로 연결됨)
*   **단일 통제소 대기열 구조(Single-Threaded Daemon Queue) 설계 확립:**
    *   **(결함 도출):** 여러 장의 불량 사진들을 사용자가 빠르게 연속 수선할 때, 백그라운드의 1:N 교집합 사진들에서 물리적 파일 이동(`shutil.move`)이 동시다발적으로 발생할 경우 심각한 충돌(`FileNotFoundError`)이 발생함을 감지.
    *   **(솔루션 확정):** 사용자의 피드백 제출을 다중 서브프로세스로 즉각 터트리지 않고, SQLite의 `feedback_tasks` 대기열에 임시 보관함. 
    *   백그라운드에서 오직 단 하나(Singleton)의 관리자 봇(`feedback_daemon.py`)이 이 대기록을 하나씩 꺼내어 "디렉토리 이동 -> 기존 Qdrant 및 파편 삭제 -> `vector_indexer` 족집게 재가동" 이 완전히 끝나야만 다음 피드백을 처리하도록 철벽 아키텍처를 도입 확정.
