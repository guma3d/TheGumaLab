# GumaPhoto 프로젝트 마스터 플랜 (가족 특화 시맨틱 검색 시스템)

이 문서는 GumaPhoto 서비스의 전체 기획과 향후 로드맵을 정의합니다. (수시로 업데이트 됩니다)

## 📌 최종 목표
- 가족 구성원의 얼굴을 학습시키고 모든 사진에서 인물, 표정, 배경(장소, 분위기) 정보를 다각도로 추출하여 벡터 DB에 영구 보존.
- 모바일(스마트폰)에서 무제한 대량의 사진을 즉각적으로 업로드하고, 백그라운드에서 실시간으로 갤러리를 정렬/분석하는 무중단 동기화 서비스 구축.
- 사용자의 자연어(예: "가족들이랑 해변가에서 웃고있는 사진", "아빠가 군복 입은 사진")를 찰떡같이 알아듣는 LLM 기반 사진 검색 엔진 개발.
- 홈서버(FastAPI+Nginx) 위에서 가족 누구나 웹/모바일로 쉽게 접근 가능한 구글 포토(클라우드 갤러리) 수준의 개인화 갤러리 런칭.

---

## ✅ 1단계: 개발 환경 구성 및 홈서버 인프라 구축 (완료)
1. **Docker 기반 환경 세팅**: `docker-compose.yml`을 통해 메인 FastAPI 애플리케이션(`gumaphoto_app`) 및 Qdrant 벡터 DB(`gumaphoto_qdrant`) 구축.
2. **홈서버 연동 지원**: `TheGumaLab` 메인 포털 인덱스에 GumaPhoto 추가 및 Nginx 리버스 프록시(`/GumaPhoto`) 매핑 완료.
3. **코드베이스 클린 아키텍처**: 뼈대 파일 4개만 루트에 남기고 약 50여 개의 진단/테스트 찌꺼기 파일들을 완벽히 폐기하여 Domain-Driven `api/` 구조로 혁신 완료.

## ✅ 2단계: 자동 스마트 분류 파이프라인(Organizer) (완료)
1. **시계열 & 메타데이터 구조화**: 기존 뒤섞인 원본 사진들을 `YYYY/YYYY-MM/YYYY-MM-DD_01.jpg` 형식의 규격화된 트리 구조로 자동 재배치.
2. **표준 한국어 위치 명칭 강제 (Geocoding)**: OpenStreetMap Nominatim 라이브러리를 통해 추출한 세계 공용 GPS 좌표를 정식 한국어 포맷(도/특광역시-시/군/구)으로 한글화 변환 반영.
3. **완벽 연속 압축 정렬 (Compress Sequence)**: 파일 구멍을 테트리스 식으로 정렬 및 해시 기반의 오차 없는 쓰레기 파일/중복 샷 영구 차단.

## ✅ 3단계: 멀티모달(얼굴+배경+사물+서사) 하이브리드 벡터화엔진 (완료)
1. **안면 인식 (InsightFace)**: 최대 수준의 안면 추출 엔진(`buffalo_l`)을 가동하여 사진에 등장한 인물들의 512차원 벡터와 성별/나이 추출.
2. **표정 분석 (HSEmotion)**: PyTorch 초경량 모델로 'Happiness', 'Sadness', 'Contempt' 등 감정 상태 분석.
3. **분위기 분석 (최신 SigLIP)**: `google/siglip` 엔진을 가동하여 피사체/색감 분위기벡터(768차원) 생성.
4. **객체 탐지/묘사 (Florence-2-base)**: MS의 최첨단 VLM으로 영문 문장 캡션 자동 저술 (OOM 방어 및 무한 루프 환각 차단용 토큰 안전망 완비).
5. **다이나믹 메타-사전 자동 갱신**: 인덱싱 작업이 끝나면 `available_tags.json` 마스터 사전을 자가 갱신.

## ✅ 4단계: FastAPI 백엔드 검색 엔진 및 UI/UX 고도화 (완료)
1. **정확 무결성 LLM 서치 시스템**: Gemini가 검색어를 유추하되, 장부(사전)에 없는 타 지역(알래스카)을 환각 변환하는 현상을 억제하도록 사전 내 존재 여부 엄격 검증 명령 프롬프트 장착. 
2. **유령 파일(Ghost File) 없는 Hard Delete**: 사용자 사진 삭제 시 물리적 원본 + XMP + Qdrant 포인트에 이어 파생 썸네일(WebP)까지 완벽 동반 소구 보장.
3. **Premium 프론트엔드 라우팅 (SPA 단계)**: 모바일 사파리의 네이티브 액션과 흡사한 Z-Index 독립 모달 탭 스위칭(`frontend/` 디렉토리 현대화). 가로 무작위 프리미엄 뽑기 카드 무조건 10개 풀충전 보장 구성.

## ✅ 5단계: 대규모 상용 엔터프라이즈 통합 백엔드 아키텍처 도입 (완료)
1. **분산 메시지 브로커 (Redis + Celery) 독립 큐**: 파일 시스템의 수십/수백 장 폭주 스파이크와 AI 모델의 VRAM 붕괴를 완벽히 막기 위해, 백그라운드 딥러닝 전용 장갑차(`celery_worker`) 컨테이너를 가동하여 완전 분산 처리 (`max_tasks_per_child=1` 로 GPU 메모리 영구 0% 스왑화 달성).
2. **통합 ORM 데이터베이스 단일 규격화 (SQLAlchemy)**: 과거 사방에 흩어져있던 날것(Raw)의 SQLite 쿼리와 `processed_files`, `vectorized_files` 잔재를 싹 지우고, 사진 1장에 대한 모든 스펙(`filepath`, 해상도 `width/height`, 용량 `bytes`)과 생사 여부(`status`) 추적을 **`Photo` 라는 단일 ORM 객체 속성 하나로 완전히 흡수 통합(Single Source of Truth)**.

## ✅ 6단계: 사용자 참여형 자율 진화 피드백 시스템 v2.0 (완료)
1. **1:N 무결점 클린 리빌드**: 사용자가 단 1장의 미분류 사진을 수선하면, AI가 벡터 유사도를 바탕으로 수십 장을 끌어모아 교정. (재인덱싱을 위해 파일 시스템 이주시 DB에 구 `Tombstone(DELETED)` 각인)
2. **Redis Celery 대기열 보호 구조**: 다수의 사용자가 피드백을 수십 번 연타하더라도 파일 이동 충돌(`FileNotFoundError`)이나 SQLite 동시성 락(Database is locked) 버그가 나지 않도록, 모든 무거운 변경과 이주를 ORM 풀링(Connection Pool)이 탑재된 단일 큐 워커가 안전하게 순차 지휘함.
3. **완전 독립형 코어 유틸리티 2종 분리 (`PhotoPurger`, `MetadataEditor`)**: 복잡하고 위험한 물리적 파쇄/삭제(Tombstone) 로직을 `PhotoPurger`로, ExifTool 지오코딩/메타데이터 주입을 `MetadataEditor` 클래스로 완벽히 격리(Decoupling)하여 범용 재사용성을 극대화.
4. **유령 폴더 영구 박멸 (Ghost Scavenger)**: 피드백으로 인해 사진이 모조리 빠져나가 텅 비어버린 껍데기 폴더들을 서버 런타임 종료 시 OS 단(`os.walk(topdown=False)`)에서 알아서 파쇄하는 백그라운드 청소망 구축.

## ✅ 7단계: 모바일 네이티브 UX 최적화 및 롤백 무결성 보장 (완료)
1. **Ghost Rollback (유령 크롭 파기)**: 오분류된 사용자의 피드백을 재수정(Re-Tag) 할 때, 과거 폴더에 잘못 저장된 `point_id.jpg` 얼굴 크롭들을 파이프라인에서 우선적으로 글로벌 서치(`glob.glob`)하여 사전 파쇄함으로써 AI 데이터셋 오염률 0% 달성.
2. **Pinch-to-Zoom 및 Focus View**: `Panzoom.js` 이식 및 터치 스크린의 `Tap-Highlight` 무효화를 결합하여, 모달 내 사진 더블탭/핀치 시 브라우저 UI 붕괴 없는 진정한 앱스토어 급 이미지 감상 환경 구현.
3. **Web Share API Level 2 (순수 물리 전송)**: Web PWA상에서 사진의 URL 링크가 공유되는 HTTP 태생적 한계를 극복. 런타임에 Blob Fetch -> File Type 캐스팅 후 넘겨주어 카카오톡, 라인 등 외부 커뮤니티 앱으로 사진 "원본 덩어리" 100% 직배송.

## 🚀 8단계: 하이브리드 3D 맵 아키텍처 (진행 중)
1. **인프라 렌더링 부트스트래핑 (Phase 1 완료)**: `/map` 엔드포인트 개통 및 CesiumJS 3D 위성 지구본 렌더링.
2. **데이터 파이프라인 구축 (Phase 2 완료)**: AI 인덱싱 워커 내부에 WGS84 좌표 추출기 병합 및 기존 2만 장 이상의 사진에 대한 초고속 GeoJSON 덤프 엔진 가동.
3. **공간 레이어링 (Phase 3 대기)**: 대한민국 VWorld 엔진 스위칭 등 로컬 지형 특화.
4. **시각화 테크니컬 아트 (Phase 4 대기)**: 그라데이션 클러스터링 기반 아트워크 및 썸네일 폴리싱 적용 예정.
