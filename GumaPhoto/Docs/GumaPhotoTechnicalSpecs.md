# 🔍 GumaPhoto 모듈별 핵심 기술 명세서 (Technical Specifications)

이 문서는 GumaPhoto 시스템을 지탱하는 **핵심 프로세스(업로드, 폴더정리, 벡터인덱싱, 삭제 처리 등)** 가 백엔드에서 어떻게 구현되고 작동하는지 상세히 기술한 테크니컬 문서입니다.

---

## 1. 📤 무중단 업로드 파이프라인 (Upload)
**[핵심 스크립트]:** `main.py` (`/api/upload` API 엔드포인트)

*   **동작 방식:**
    1.  스마트폰이나 브라우저에서 다중 파일을 비동기(FormData) 형태로 전송합니다.
    2.  서버 메모리가 폭발하지 않도록, 들어오는 즉시 청크(Chunk) 라인 단위로 읽어 디스크의 `app/data/uploads_raw/` 라는 대기열(Queue) 전용 임시 폴더에 파일 포맷 그대로 쏟아 놓습니다.
    3.  파일 수신이 모두 완료되면 프론트엔드에 즉각 `200 OK`를 리턴하여 **모바일 화면이 멈추거나 튕기는 현상을 원천 방어(Zero-Blocking)** 합니다.
    4.  그 직후 FastAPI의 `BackgroundTasks` 트랙을 점화시켜, `organizer_pipeline.py` 스크립트를 백그라운드 무자각 상태로 부팅시킵니다.

## 2. 🗃️ 시계열 폴더 정리 및 찌꺼기 청소 (Organizer Pipeline)
**[핵심 스크립트]:** `organizer_pipeline.py`

*   **동작 방식:**
    1.  `uploads_raw/` 에 대기 중인 파일들을 한꺼번에 메모리에 올리지 않고 VRAM 오버플로우 방지를 위해 **200장 단위(Batch)** 로 쪼개어 프로세싱을 시작합니다.
    2.  **Junk 필터링 (Hash 검사):** `organizer_state.db`에 저장된 이전 파일들의 MD5/SHA256 해시값과 대조하여 영리하게 완전 복제된 사본을 발견 즉시 영구 파기시킵니다. 또한 영수증 비율, 심각한 블러(흔들림)가 포함된 스크린샷 류의 파일들도 2차적으로 제거합니다.
    3.  **메타데이터 추출 (EXIF):** 남은 정상적인 사진에서 EXIF 데이터를 까서 `Date(촬영일자)` 와 `GPS(위경도)` 를 추출해 냅니다.
    4.  **표준 한국어 역추적 지오코딩 (Nominatim KO):**
        - 추출된 GPS 좌표를 OpenStreetMap API(`language='ko'`)에 던집니다.
        - 파리(Paris), 하와이(Hawaii) 등 전 세계 어디에서 찍었든 **"[국가/도]-[도시/구]"** 형태의 완벽한 100% 한글 표준 명칭(예: `미국-호놀룰루`, `경기도-성남시`) 만을 반환받습니다. (실패 시 "위치정보없음" 부여)
    5.  **디렉토리 트리 안착 연산 및 이름 충돌 방어:**
        - `{Date}_{Location}` 이라는 정규 폴더(예: `2019/2019-03_경기도-성남시/`)를 자동 생성합니다.
        - 그리고 그 안에 `2019-03-12_01.jpg` 형태로 일련번호를 매겨 넣습니다. 이때 `.heic` 나 `.jpg` 기종 차이로 `_01` 번호판이 겹치는 파괴 현상을 막기 위해, 확장자를 배제한 강력한 ฐาน 파일명(Base Glob) 조회 탐색기를 발동시킵니다. 중복 시에는 무조건 빈자리나 가장 뒷번호로 밀어 넣어 파일 덮어쓰기(Overwrite)를 0순위로 원천 차단합니다.
        - 이 모든 방패를 뚫고 나면, 파일은 `shutil.move` 를 통해 최종 보관소(`organized/`)로 입주합니다.

## 3. 🌌 다중 딥러닝 벡터 스캐너 (Vector Indexer)
**[핵심 스크립트]:** `vector_indexer.py`

*   **동작 방식:** 폴더 정리가 끝난 직후 `main.py`에 의해 바로 이어달리기 배턴 터치를 받아 가동되는 심층 스캐너입니다.
    1.  **배치 프로세싱 & 리스캔 방지:** 디렉토리를 싹 훑은 다음, 이미 이전에 작업해 둔 녀석들은(Qdrant에 값이 살아있다면) 철저하게 패스합니다. (재작업은 기존 태그가 완전히 부서졌을 때만 Clean State 삭제 후 진행)
    2.  **다중 모델 컨베이어 벨트 (CPU-GPU 멀티스레드 분산):** 
        - **InsightFace:** 이미지 속 가족 얼굴 위치와 특징점(512D) 추출
        - **HSEmotion:** 추출된 얼굴의 표정을 읽어 감정 텍스트 할당
        - **Florence-2-base:** 원본 이미지를 통째로 읽어 구체적인 영단어 나열(objects)과 소설 같은 긴 영어 묘사(caption) 생성 (`bfloat16` 정밀도 및 Eager 모드 최적화로 속도/VRAM 극대화. 할루시네이션 방지를 위한 `repetition_penalty=1.5`, `max_new_tokens=256` 제한 적용)
        - **SigLIP:** 이미지를 보고 다국어적 시각 분위기를 압축하여 고밀도(768D) 공간 벡터 생성
    3.  위 4개의 거대 모델이 8GB VRAM이라는 좁은 풀 안에서 터지지 않고 OOM(Out of Memory) 스파이크를 완벽히 버텨내도록, **BATCH_SIZE를 10장** 단위로 강력하게 조율한 안정적인 직렬(Sequential) 메모리 점유 구조로 설계되어 있습니다.
    4.  **마스터 사전(Dictionary) 자동 교체:** 루프를 돌며 발견된 모든 사진의 폴더 지역명칭들을 리스트로 모조리 취합하여 나중에 Gemini 파서 엔진이 커닝할 수 있도록 `/app/data/available_tags.json` 파일에 자가 업데이트 합니다.

## 4. 🪦 3단 연속 하드 딜리트 파이프라인 (Hard Delete)
**[핵심 스크립트]:** `main.py` (`/api/delete_photo` API 엔드포인트)

*   **동작 방식:** 스마트폰에서 휴지통 아이콘을 누르면, 더미 데이터의 잔류를 아득바득 막아내는 3중 Hard-Delete 연쇄 파괴 프로세스가 발동합니다.
    1.  **File System 1차 소각:** 실제 원본 파일(`os.remove`) 파기. 이어서 기생하고 있던 XMP 메타 파일(`.xmp`) 파기. 가장 잊기 쉬운 고속 로딩용 썸네일(`_wepp` 변환 파일)까지 모조리 파기. 
    2.  **Vector Store 2차 소각:** Qdrant 서버에 접속하여, 이 사진이 남겼을 그 당시의 768차원, 512차원 점 포인트들을 ID값 기반으로 색출하여 완전 멸각.
    3.  **Local DB 3차 묘비(Tombstone) 세우기:** SQLite `vectorized_files` 레코드에 이 파일은 `DELETED` 상태임을 강제 각인. 만에 하나 추후 Indexer가 이 파일을 캐시에서 또 발견하더라도, "이건 주인이 버린 거다" 라고 인식하고 부활(Re-index) 시키지 않게 막는 사후 봉쇄입니다.

## 5. 🧬 자율 진화 피드백 시스템 v2.0 (Self-Healing Feedback & Clean Re-Build)
**[핵심 스크립트]:** `feedback_daemon.py`, `feedback_processor_v2.py`

*   **동작 방식 (1:N 시각 군집 확장 및 무결점 리인덱싱):** 사용자가 누락된 미분류 정보(Unknown)를 1장만 채워주면, AI가 유사한 벡터를 찾아내어 대규모로 일괄 수정을 진행하는 자율 치유 설계입니다. 핫-패치를 버리고 원본 영구 보존과 벡터 정밀도 100% 무결성을 극한으로 추구합니다.
    1.  **단일 질의 및 시각 군집화 (Vector Similarity Clustering):** 
        - 시간/장소가 'Unknown'인 수집 사진 중 랜덤(Limit 500)으로 뽑아 단 1장만 UI에 띄워 사용자에게 질의합니다. (테스트용 물리적 최신순 정렬 기능도 내장 보존)
        - 사용자가 정답(시간/장소)을 입력("Send")하면, Gemini AI가 이를 `YYYY-MM` 등 표준 포맷으로 변환하고, 해당 사진의 초거대 상황 벡터(SigLIP 768D) 거리가 매우 유사한 주변의 N장 사진들을 자동으로 색출해 '수정 타겟 리스트'로 엮습니다.
    2.  **안면 피드백 보류 (On-Demand Face Enrollment Standby):**
        - (UX 제약 사항): 사진 속 여러 명의 Unknown 인물이 있을 때 누구를 가리키는지 특정하기 위해 박스(Crop)를 치고 보여줘야 하는 UI 기술적 한계가 존재하여, 현재 피드백 탭 통계 풀에서 인물 피드백은 0% 확률로 팝업되도록 의도적으로 배제(Disable)해 두었습니다.
    3.  **결손 데이터(시간/장소) 동등 무작위 선별 로직:**
        - 위치정보없음(Location Missing)이 압도적으로 많은 현상을 타파하기 위해, 기존의 `if-elif` 우선순위 필터를 폐기했습니다. 장소나 시간 정보가 누락된 모든 경우의 수를 배열에 모아 1/N 확률(Random Choice)로 동등하게 1장을 뽑아 사용자 화면에 올립니다.
    4.  **100% 무결점 클린 리빌드 (Clean Re-Index) 및 ExifTool 주입:**
        - 타겟에 속한 사진들의 기존 파생 찌꺼기(XMP, 썸네일 WebP, SQLite 추적 기록, Qdrant 벡터)를 모조리 클린 삭제(Drop)합니다. 이때, Qdrant 검색 시 수 분의 캐시 지연 현상을 막기 위해 `exact=True` 통계를 사용하여 UI 모니터링 펜딩 버그를 해결했습니다.
        - 올바른 날짜/장소 데이터를 윈도우 탐색기나 기본 `exifread` 모듈이 아닌, 산업 표준 최강의 **`exiftool`을 사용하여 타겟 본체(PNG, HEIC, MP4 무관)에 직접 하드코딩(Overwrite)** 합니다.
        - 수술이 끝난 파일을 `uploads_raw`로 다시 돌려보내면, `organizer_pipeline.py` 가 `exiftool -j` 를 역호출하여 바뀐 데이터를 인식하고 완벽하게 새 폴더로 이주(`shutil.move`)시킵니다.
    5.  **🚨 단일 통제소 대기열 구조 (Single-Threaded Daemon Queue):**
        - **(문제점 방어):** 사용자가 재미를 느껴 연속으로 피드백을 날릴 경우, 1번 작업이 수백 장의 파일 이동(shutil)을 진행하는 도중에 2번 작업이 겹치는 타겟 파일을 찾다가 `FileNotFoundError` 동시성(Concurrency) 접근 충돌이 발생하는 치명적 약점을 방어합니다.
        - **(해결책 구현):** 사용자가 피드백 UI의 Send 버튼을 누르는 순간, 즉각 0.05초 만에 SQLite의 `feedback_tasks` 대기열(Queue) 장부에 유저의 수정 지시서만 툭 던져 넣습니다.
        - **(버퍼 데드락 차단):** 백그라운드에는 거미줄처럼 파생되는 멀티스레드가 아니라, 단 1명의 감독관 봇(`feedback_daemon.py`)이 상주합니다. 이 때 AI 서브프로세스의 Pipe Buffer Full 록(Hang-up) 현상을 원천 방어하기 위해 `stdout=sys.stdout` 으로 출력을 부모와 연결하여 메인 무중단 파이프라인을 완성했습니다. 봇은 장부에서 지시서를 꺼내 모든 파일 이동과 재스캔(`vector_indexer`)이 끝날 때까지 묵묵히 동시성을 통제합니다.

## 6. 📸 자연어 하이브리드 검색 엔진 (Search Architecture)
**[핵심 스크립트]:** `main.py` (`/api/search` API 엔드포인트)

사용자가 검색창에 "우리 가족이 하와잌 해변가에서 노는 거 보여줘"라고 자연어로 요청했을 때 작동하는 4단계 지능형 검색 기어입니다.

1. **마스터 사전을 참고하는 LLM 정밀 파싱 (Gemini)**
   - AI 도우미 Gemini가 사용자의 문장을 듣자마자 자신의 뇌피셜로 결과를 짜내지 않고, 3단계 인덱서가 만들어준 **<보유 장소 목록 사전>**을 슬쩍 커닝합니다!
   - `people`: `["가족 이름 맵핑"]` 
   - `location`: `["미국-하와이"]` ("하와잌" 같은 오타를 기가 막히게 교정하여 사전에 있는 "미국-하와이"에 완벽 매칭합니다)
   - **[할루시네이션(환각) 억제]**: 사전에 없는 타 지역("알래스카 해변")을 쳤다면, AI는 똑똑하게 `""`(빈 값)을 제출하여 없는 곳을 찾아 헤매는 헛짓거리를 완전히 차단합니다.
   - `scene`: `"playing at the beach"` ('해변가'라는 상황만 별도로 순수 영문 번역)

2. **철통 방어, 1차 수문장 '하드 필터' (Must Condition)**
   - 추출된 `people`과 `location`은 **"무조건 있어야만 하는 교집합 필터"**로 작동하여 다른 인물을 100% 쳐냅니다.

3. **무한 탐색 '벡터 검색' (가중치 70%)**
   - 하드 패스가 완료된 사진들을 대상으로, 파싱된 `scene` 영어 문장의 느낌(파도, 모래사장 등)을 768차원 SigLIP 공간에서 가장 거리가 가까운 100장만 퍼올립니다.

4. **캡션 정밀 단어 매칭 '리랭킹' (가중치 30%)**
   - 퍼올린 100장의 사진 속 Florence가 쓰여둔 영어 캡션 문장과 검색어 단어의 일치율(Overlap Score)을 최종 합산하여 등수를 매깁니다.

5. **🚨 예외 상황 및 '스마트 폴백(Fallback)' 발동**
   - 1차 필터링 결과가 0장이 나오면, 즉각 `장소`와 같이 지나치게 타이트한 필터 족쇄를 스스로 풀고, `사람` + `분위기 유사도 검색` 만으로 기어를 낮춰 "장소가 비록 틀렸어도 가장 분위기 일치도가 높은 사진"을 제공하는 우아한 성능 저하(Graceful Degradation) 기능이 준비되어 있습니다.
