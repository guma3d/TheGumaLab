# GumaVideoFactory 제작 최우선 규칙

- 제품 외형의 정확성이 영상 미감보다 우선한다. 실제 제품과 다른 외형을 제품 소개 이미지·영상으로 사용하지 않는다.
- 제품 외형 컷은 정확한 모델의 실제 상품 사진/검증된 실제 영상 또는 사용자가 외형을 확인·승인한 Blender 모델로 제작한다. AI 참조 이미지 입력만으로 외형 일치를 보장했다고 판단하지 않는다.
- 현재 생성형 파이프라인에서는 실제 제품 사진 컷을 AI 이미지 생성이나 Veo에 넘기지 않는다. 사진을 그대로 사용하는 FFmpeg 렌더만 허용한다.
- 테크는 공식 클립을 기본으로 자체 설명·선택적 3D를 보탠다. 원본 시간표·기능 일치를 검증하고 오디오는 제거한다. 공식 재사용은 사용자 작업 가정으로 기록한다. 형상 미확보 시 원리 표현으로 표시하며 내부 구조를 꾸미지 않는다.
- 09·21시마다 Codex가 새 제품 3개의 공식 클립·대본·필요한 3D를 로컬에서 준비·검수한다. 사전 유료 API는 금지하며 검수 해시로 준비 완료를 판정한다. 웹에서는 전체 묶음을 최종 승인하고 Veo 전환·최종 합성을 실행한다. 형상 미확보는 명시적인 원리 3D로 표현한다.
- 승인된 모델 컷은 Blender에서 직접 렌더링한다. 외형을 Veo로 재생성하거나 임의로 바꾸지 않는다. 다운로드 파일의 스크립트·드라이버를 실행하지 않는다.
- 새 작업은 아이디어별 상세 페이지에서 관리한다. `storage/products/<product-id>/{3DModel,Preview,Video}/vNNNN`에 단계별 결과·출처·승인·부모 버전을 기록한다. 재생성은 새 폴더에 저장하며 이전 결과를 덮어쓰지 않는다.
- 기존 Blender 모델 수정도 반드시 새 3DModel 버전으로 저장한다. `parent_model_version`·수정 내용·원본 해시를 기록하고 승인을 초기화한다. 제품이 여러 대인 원본은 검증된 기종·치수 근거로 한 대의 전체 부품 그룹을 선택한다. 첫 번째 메시나 큰 메시를 임의로 고르거나 버튼·렌즈 부품을 제거하지 않는다.
- 제작은 저장형 FIFO 큐에서 순차 실행한다. 버튼에 대기 순번·진행 상태를 표시하고 제목만 상세로 이동한다. 미시작 작업은 재시작 후 재개하며 승인을 유지한다.
- 사용자가 제시한 Instagram 영상은 퀄리티·3D 연출 참고다. 제품 외형을 바꾸거나 원본 주제·대본을 모방할 근거가 아니다.

## 피드백을 코어에 반영하는 원칙

- 제품 테스트에서 받은 피드백은 해당 파일의 수정뿐 아니라 공통 원인과 적용 범위를 판단해 코어 로직에 반영한다. 다른 제품에도 적용되는 규칙은 `app/core/production_rules.json`의 규칙·피드백 이력과 revision을 함께 갱신한다.
- 검색·사진 기반 모델 재구성·콘티 기획은 공통 제작 컨텍스트를 사용한다. 각 신규 제작 버전은 적용한 규칙 사본·revision·해시를 기록한다. 과거 이력은 변경하지 않는다.
- 아이폰 전용 치수·형상·부품 수를 다른 제품에 일반화하지 않는다. 제품 외형 검증, 정적 PBR·UV 보존, 단일 완제품 선택, 승인·버전 관리는 공통 코어에서 처리한다. 정확한 기종 선택 근거가 없으면 임의로 잘라내지 않는다.
- 공통 수정은 다른 제품명·형상·UV 자료로 검증한다. 유료 생성은 요청 범위에 한정한다. 피드백 시 관련 MD의 낡은 내용을 교체·통합하고 전체 분량을 늘리지 않는다. 이력은 Git으로 보존한다.
