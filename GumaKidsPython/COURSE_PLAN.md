# 초등 3학년 파이썬 게임 업그레이드 강의 설계

## 목표

초등학교 3학년 아이가 파이썬을 "문법 공부"가 아니라 "게임을 업그레이드하는 놀이"로 경험하게 만든다.

- 총 48챕터
- 주 3회 진행 기준 약 16주 과정
- 4개의 완성된 게임을 시즌별로 사용
- 각 시즌은 12챕터씩 구성
- 챕터 1~2만 1줄을 바꾸고, 챕터 3부터 2줄 이상을 바꾸며, 시즌 1 마지막 챕터 12에서는 10줄 수준의 종합 업그레이드를 한다
- 모든 챕터는 그날 배운 기능만으로 미션을 해결할 수 있어야 한다
- 기준 실행 환경은 웹버전 하나만 사용한다

## 핵심 운영 원칙

1. 하루에 핵심 기능 1개만 배운다.
2. 어려운 기능은 여러 챕터로 나누어 배운다.
3. 처음부터 게임 전체 코드를 만들지 않는다.
4. 미리 완성된 게임에서 아이가 오늘 배운 부분만 업그레이드한다.
5. "수정"보다 "업그레이드"라는 표현을 사용한다.
6. 실패해도 다시 실행하면 된다는 감각을 계속 준다.
7. PDF는 공부 교재보다 게임 퀘스트북처럼 보이게 만든다.

## 4개 시즌 게임 구조

| 시즌 | 챕터 | 게임 이름 | 주요 학습 |
|---|---:|---|---|
| 시즌 1 | 1~12 | 보물 점수 게임 | 출력, 문자열, 숫자, 변수, 계산 |
| 시즌 2 | 13~24 | 던전 선택 게임 | 입력, 조건문, 비교, 논리 연산 |
| 시즌 3 | 25~36 | 몬스터 배틀 게임 | 반복문, 리스트, 딕셔너리, 게임 데이터 구조 |
| 시즌 4 | 37~48 | 미니 어드벤처 게임 | 함수, 클래스/객체 기초, 랜덤, 저장, 예외, 종합 |

## 교육 내용 점검 및 보강 기준

현재 48챕터 흐름은 기초 값 조작, 조건 판단, 반복과 자료 모음, 함수와 종합 제작으로 이어진다. 큰 흐름은 유지하되, 게임 개발에서 중요한데 부족했던 개념은 아래 기준으로 보강한다.

| 점검 항목 | 기존 상태 | 보강 방향 |
|---|---|---|
| 구조체처럼 데이터를 묶는 법 | 딕셔너리가 시즌 3 마지막 1챕터에만 있음 | 시즌 3 후반에 딕셔너리와 리스트 안의 딕셔너리를 반복하고, 시즌 4에 `class`와 객체 속성 접근을 추가 |
| 참/거짓 상태값 | 시즌 2 조건문 안에 숨어 있음 | `has_key`, `has_gem` 같은 상태값을 Boolean 개념으로 명시 |
| 자료 모음 활용 | 리스트 추가/삭제 중심 | 아이템 카드 목록, 몬스터 카드처럼 게임 오브젝트 데이터로 연결 |
| 모듈 사용 | 랜덤/시간에서만 등장 | `random`, `time`은 `import` 개념을 함께 설명 |
| 저장과 예외 | 파일 읽기/쓰기가 분리되어 있음 | 저장/불러오기를 한 챕터로 묶고, 바로 다음 챕터에서 예외 처리로 안정성 설명 |

Python에는 C/C++이나 Unreal의 `struct`와 완전히 같은 문법은 없지만, 초급 과정에서는 딕셔너리를 "이름표가 붙은 값 묶음"으로 먼저 배우고, 후반에는 `class`를 "캐릭터 설계도"로 소개한다.

## 시즌 1: 보물 점수 게임

주인공이 보물을 먹으면 점수가 오르고, 함정에 닿으면 체력이 줄어드는 간단한 게임이다.  
아이는 주인공 이름, 대사, 시작 점수, 체력, 보물 점수, 함정 데미지 등을 바꾸며 파이썬 기초를 배운다.
`hero_message`는 주인공 옆 말풍선으로 표시하며, 캐릭터가 움직일 때 함께 따라다녀야 한다.
시즌 1은 챕터가 진행될수록 시작 깃발, 말풍선, 이름표, 보물상자, 보물, 체력, 속도 부스터, 상태창, 함정, 보너스, 포털이 누적되어 게임이 점점 완성되는 구조로 만든다.

| 챕터 | 제목 | 오늘의 업그레이드 | 게임에 생기는 것 | 배우는 기능 | 수정 줄 수 | 아이가 바꿀 코드 | 놀이미션 | 퀴즈 방향 |
|---:|---|---|---|---|---:|---|---|---|
| 1 | 게임 화면아 안녕 | 게임 시작 문장 바꾸기 | 시작 깃발과 첫 장면 | 문자열 `str` | 1 | `start_message` | 시작 문장을 자기 말로 바꾸기 | 따옴표 안의 글자와 문자열 |
| 2 | 캐릭터가 말해요 | 주인공 대사 바꾸기 | 따라다니는 말풍선 | 문자열 `str` | 1 | `hero_message` | 주인공에게 멋진 대사 주기 | 문자열과 `str` 개념 |
| 3 | 이름을 바꿔요 | 주인공 이름과 시작 점수 바꾸기 | 이름표와 이름 깃발 | 문자열과 숫자 구분 | 2 | `hero_name`, `start_score` | 이름과 시작 점수 조합 3개 만들기 | 문자열과 숫자 구분 |
| 4 | 숫자가 보여요 | 시작 점수와 체력 바꾸기 | 보물상자와 상태창 점수 | 정수 `int` | 2 | `start_score`, `hp` | 시작 점수와 체력을 함께 바꿔보기 | `int`와 문자열 구분 |
| 5 | 점수판 만들기 | 점수와 보물 점수 만들기 | 보물/동전 수집 | 변수와 대입 | 3 | `start_score`, `score`, `treasure_point` | 보물 게임의 시작 점수와 보상 정하기 | `=` 오른쪽 값의 저장 위치 |
| 6 | 체력 만들기 | 점수, 체력, 함정 피해 조절 | 체력 하트와 체력 UI | 숫자 변수 | 4 | `start_score`, `score`, `hp`, `trap_damage` | 체력과 함정 피해 조합 비교하기 | `hp`에 들어 있는 값 |
| 7 | 속도 만들기 | 속도까지 포함해 난이도 조절 | 바람신발과 질주 효과 | 변수 값 변경 | 5 | `start_score`, `score`, `hp`, `speed`, `trap_damage` | 느린/빠른 캐릭터와 위험도 비교 | 값이 바뀌면 결과도 바뀜 |
| 8 | 글자 합체 | 이름, 대사, 등장 문장 합치기 | 등장 문장 아치 | 문자열 연결 `+` | 6 | `hero_name`, `hero_message`, `start_score`, `score`, `speed`, `title` | 내 이름이 들어간 등장 문장 만들기 | `+`가 글자에서 하는 일 |
| 9 | 멋진 상태창 | 상태창에 여러 값 넣기 | 게임 안 상태창 | f-string | 7 | `hero_name`, `hero_message`, `start_score`, `score`, `hp`, `speed`, `status_text` | 게임 상태창 문장 만들기 | `{}` 안에 넣는 값 |
| 10 | 더하기 마법 | 보물 점수까지 포함해 규칙 조절 | 큰 보물과 콤보 | 덧셈 `+` | 8 | `hero_name`, `start_score`, `score`, `hp`, `speed`, `title`, `status_text`, `treasure_point` | 보물을 먹으면 50점 오르게 하기 | 계산 후 점수 예측 |
| 11 | 빼기 마법 | 함정 데미지까지 포함해 규칙 조절 | 움직이는 함정과 피해 | 뺄셈 `-` | 9 | `hero_name`, `start_score`, `score`, `hp`, `speed`, `title`, `status_text`, `treasure_point`, `trap_damage` | 함정 데미지를 약하게/강하게 만들기 | 체력 계산 |
| 12 | 보너스 점수 | 시즌 1 전체 규칙 종합 업그레이드 | 보너스별, 포털, 승리 연출 | 곱셈 `*` | 10 | `hero_name`, `start_score`, `score`, `hp`, `speed`, `title`, `status_text`, `treasure_point`, `trap_damage`, `bonus_multiplier` | 보너스 점수 2배, 3배 만들기 | 곱하기 결과 |

## 시즌 2: 던전 선택 게임

문, 열쇠, 비밀번호, 무기 선택, 보물상자가 있는 던전 게임이다.  
아이는 입력과 조건문을 사용해 게임 규칙을 업그레이드한다.

| 챕터 | 제목 | 오늘의 업그레이드 | 배우는 기능 | 아이가 바꿀 코드 | 놀이미션 | 퀴즈 방향 |

## 시즌 3: 몬스터 배틀 게임

## 시즌 4: 미니 어드벤처 게임

## PDF 한 챕터 기본 페이지 구성

각 챕터는 5페이지 안팎을 기본으로 한다.
설명이 더 필요한 챕터는 8~10페이지까지 늘릴 수 있지만, 최대 10페이지를 넘기지 않는다.

1. 표지: 오늘의 게임, 오늘의 업그레이드
2. 오늘의 코드: 따라 치는 코드 1~10줄
3. 코드가 한 일: 초등 3학년 눈높이 문법 설명
4. 바꿔보기 또는 Play 해보기
5. 업그레이드 미션과 퀴즈
6. 정답과 짧은 해설: 정답은 마지막 페이지에만 배치

챕터 1처럼 자료형 설명이 필요한 경우에는 중간 설명 페이지를 추가해 8페이지 구성으로 만들 수 있다.

시즌 1은 챕터 1~2에서 1줄 수정으로 시작하고, 챕터 3부터 2줄 이상을 수정한다. 이후 챕터가 진행될수록 수정 줄 수를 늘려 마지막 챕터 12에서는 10줄 수준의 종합 업그레이드를 한다.
각 챕터 강의자료에는 `str`, `int`, 변수, 대입, f-string, 연산자, Boolean, 리스트, 딕셔너리, 클래스처럼 아이가 배워야 하는 문법을 쉬운 말로 반드시 설명한다.

### 지난 업그레이드 복습 페이지 규칙

- 챕터 1은 복습 대신 "파이썬 모험을 시작하기 전에" 페이지로 구성한다.
- 챕터 2부터는 이전 챕터의 핵심 코드 1개만 다시 보여준다.
- 복습 질문은 1~2개만 넣는다.
- 아이가 다시 말로 대답할 수 있는 수준으로 만든다.
- 복습 페이지에서 새 개념을 설명하지 않는다.

복습 페이지 예시:

```text
지난 시간 코드
print("모험 시작!")

기억해 볼까?
이 코드는 화면에 무엇을 보여줬을까?
```

## 웹버전 제작 계획

웹앱 안에 4개의 완성된 시즌 게임을 제공한다.
각 게임은 "완성본"이지만, 챕터별로 아이가 바꿀 수 있는 업그레이드 영역을 명확히 분리한다.

### 공통 구조

- `web/index.html`: 강의자료, 코드 편집기, 게임화면 레이아웃
- `web/app.js`: 챕터별 코드 생성, 코드 파싱, 게임 실행, 저장 연동
- `web/style.css`: Dark 테마 UI와 게임 화면 스타일
- `server.py`: 웹 정적 파일 제공과 저장 API
- `Docs/`: PDF/PNG 강의자료
- `tools/`: 강의자료 생성 도구

### 아이가 보는 코드 원칙

초반 예시:

```python
hero_name = "번개용사"
score = 10
treasure_point = 50
```

중반 예시:

```python
if has_key:
    open_door()
else:
    show_message("문이 잠겼어!")
```

후반 예시:

```python
def attack(power):
    damage = power * 2
    return damage
```

### 게임 구현 방식

초등학생 대상이고 설치 부담을 줄이기 위해 게임은 브라우저에서 바로 동작하게 만든다.

- 아이는 웹 화면의 `upgrade_zone.py`만 바꾼다.
- Play 또는 업그레이드 적용 후 결과가 같은 화면의 게임 영역에 바로 나타난다.
- 직접 실행용 `main.py`, `engine.py`, `games/` 폴더, `tkinter` 앱은 사용하지 않는다.
- 저장은 웹 저장 API와 브라우저 상태를 기준으로 설계한다.
- 게임 로직을 추가할 때는 `web/app.js` 안의 시즌별 렌더/입력/파싱 흐름을 우선한다.
